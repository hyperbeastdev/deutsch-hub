# Design brief

## Current state

The current interface uses Tailwind utility classes, an Inter web font, mobile-centered layouts, many rounded surfaces, gradients, shadows, color-coded badges and emoji labels. There is no semantic token layer, dark-mode system or complete browser QA evidence. The first audit could not perform full browser-control QA because the browser-control runtime was unavailable.

## Target state

Deutsch Hub should feel calm, intelligent, warm, focused and intentional. Design attention should go to:

- the next learning action;
- German word form, article, plural and example context;
- review confidence and progress;
- clear recovery from network or AI failure.

Use a quiet neutral canvas, a restrained accent palette, readable type, generous but disciplined spacing and modest elevation. Color should encode meaning rather than decorate every surface.

## Research process

When research tools are available, inspect interaction principles from relevant language-learning products, Figma work and accessibility guidance. Do not copy external products and do not make the project depend on Figma or Mobbin.

## Validation

Every major flow needs responsive, keyboard, reduced-motion, loading, empty, error, offline, light and dark checks. Code compilation is not visual validation.

## Open decisions

- Final color temperature and accent hue.
- Whether the wordmark uses a flag motif or a neutral language mark.
- Desktop information architecture and navigation model.
- Exact review-card interaction and rating vocabulary.
